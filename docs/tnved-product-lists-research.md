# Товарные перечни и понятные названия ТН ВЭД для календаря

Исследование: 18 сентября 2026 года. Изменения приложения не выполнялись.

## Решение

Технически реализуемо. Перечни групп доступны на публичных страницах ЧЗ без личного кабинета. Часть бытовых названий уже опубликована рядом с кодами. Для расшифровки отдельных кодов можно использовать официальную номенклатуру ЕЭК, сохраняя контекст родительских позиций и ограничения перечня ЧЗ.

Рекомендуется справочник внутри календаря: понятное название на первом плане, исходные коды, условия и ссылка на источник — в подробностях. Это перечень видов продукции, а не каталог конкретных марок, артикулов и GTIN и не автоматическое заключение об обязательности маркировки конкретного товара.

## Что проверено

Публичные страницы получены обычными HTTP-запросами с российской локальной машины. На страницах ниже товарные таблицы находятся непосредственно в HTML; запуск браузера для их получения не потребовался. Это проверка четырёх групп, а не подтверждение единого формата всех групп ЧЗ.

## Публичный поиск ЧЗ и его ограничения

Страница: https://честныйзнак.рф/checking_codes/ . В опубликованном JavaScript страницы обнаружены вызовы компонента `dev:codeSearch` через `/bitrix/services/main/ajax.php` с `mode=class`:

- `getByTypeProductHints`, параметр `q`: подсказки бытовых названий;
- `getByTypeProduct`, параметр `inputValue`: поиск по названию;
- `getByTnVed`, параметр `inputValue`: поиск по коду;
- также в коде страницы есть `getByOkpd` и `getByTnVedOkpd`, их ответы в этом исследовании не проверялись.

Проверенные запросы возвращают JSON после обычного открытия публичной страницы и передачи CSRF-токена анонимной сессии. Вход в ЛК и ключ API не потребовались. Прямой запрос без сессии возвращает `Invalid csrf token`. Секреты и сессии в приложение переносить не нужно.

Наблюдения:

- Подсказки по слову «шампунь» содержат бытовые варианты, но объединяют их в общую товарную группу первой волны.
- Запрос кода `3305100000` возвращает вторую волну, ссылку на перечень, условия и исключения. Это не готовый справочник точных наименований каждого кода.
- Подсказки по слову «посуда» вернули пустой список. Из этого нельзя делать вывод об отсутствии посуды в перечнях: таблица товаров для дома её содержит.
- Поиск по названию прямо предлагает дополнительно проверять ТН ВЭД и ОКПД2. Поэтому даты из общего поиска по названию нельзя автоматически назначать каждому найденному товару.

Это внутренние запросы публичного сайта. Документированный контракт массовой выгрузки всех перечней и гарантия стабильности этого интерфейса в изученных материалах не найдены. Использовать его единственным источником не рекомендуется.

Официальное пояснение ЧЗ: https://markirovka.ru/knowledge/tovarnye-gruppy/obschie-voprosy-gis/kak-uznat-kod-tn-ved-eaes-okpd-2-tovara . В нём указаны справочный характер сервиса, неполное покрытие экспериментальных групп и необходимость определять код по документам товара. Название помогает найти нужный раздел, но не заменяет проверку условий конкретной группы.

## Связь с текущим проектом

- `src/MarkingCalendar.Core/Events/CalendarEvent.cs`: событие содержит группу, даты, описание и ссылку; полей товарного перечня и кодов нет.
- `src/MarkingCalendar.UI/src/render.ts`, функция `markedGoodsUrl`: кнопка открывает внешний адрес, добавляя `/mark_goods/` ко всем группам.
- Для товаров для дома и игрушек это неверный адрес: реальные ссылки в меню ЧЗ ведут на `/marking_goods/`. Неверный путь возвращает HTTP 200 и оболочку страницы без товарной таблицы, поэтому одной проверки HTTP-статуса недостаточно.
- `src/MarkingCalendar.App/Web/AppViewModelFactory.cs`: список отображаемых групп формируется из событий календаря. Наличие группы в справочнике или появление товаров в ЛК не равнозначно появлению календарного события.
- Уже имеется централизованное получение данных через runner и канал данных. Его можно расширить отдельным файлом товарных перечней, не создавая новый сервис и не заставляя каждую установленную программу обходить сайт.

## Минимальный план реализации

1. Указать точные URL перечней в существующем справочнике групп; начать с товаров для дома, косметики и бакалеи.
2. Извлекать таблицы, примечания и готовые понятные наименования. Сохранять исходный код как строку: ведущие нули и укрупнённые позиции должны сохраняться.
3. Добавить проверенные расшифровки только для кодов из этих перечней. При названии «прочие» учитывать родительскую позицию. Не пытаться разворачивать весь ТН ВЭД или генерировать юридические условия с помощью ИИ.
4. Хранить вместе название, коды ТН ВЭД и ОКПД2, ограничения, исходную формулировку, источник и дату проверки. Понятная подпись не должна менять охват исходного перечня.
5. Загружать справочник существующим механизмом обновления данных. При сбое получения или исчезновении таблицы сохранять последнюю успешную версию. Изменения перечня учитывать отдельно от изменений дат календаря.
6. В карточке группы открыть раздел «Какие товары входят» с поиском по названию и коду. Название видно сразу; коды, исключения и первоисточник доступны рядом или в подробностях. Поддержать просмотр сохранённого справочника без сети.
7. Проверить три выбранные группы, сохранность исключений и актуальной версии при ошибке источника. После этого расширять охват на другие группы с учётом их форматов.

Первичная подготовка коротких подписей потребует сверки. Дальше автоматически получать изменения источника можно; новые неоднозначные расшифровки следует проверять перед публикацией. Условия массового повторного использования материалов и SLA сайта данным техническим исследованием не устанавливались.

## Реализация пилота

18.09.2026 подготовлены три встроенных перечня, 111 проверенных расшифровок и независимый сборщик обновлений. Исходные ограничения сохранены; один неоднозначный код ЧЗ оставлен без расшифровки. Инструкция: [Сопровождение товарных перечней](product-lists.md).
