# Сопровождение товарных перечней

Сборщик обходит все 50 записей `assets/groups/groups.json`. На 18.09.2026 доступны 49 официальных перечней; старые страницы группы «Средства гигиены» (`chemistry`) возвращают HTTP 404. Подтверждённой ссылки на преемника нет, поэтому вместо подмены косметикой группа остаётся в проверке и сообщениях об ошибках. В карточке без загруженного перечня приложение прямо сообщает о его недоступности.

Точные адреса хранятся в `assets/groups/groups.json`, поле `goodsUrl`; они проверены по навигации самих страниц ЧЗ. Например, икра использует `/marking/`, пиво — `/marking_goods_beer/`. Статус завершённого эксперимента не исключает группу из справочника. Товарные названия извлекаются из HTML, а не прописываются в приложении.

## Как проходят обновления

`build/products.py` использует только стандартную библиотеку Python 3. В GitHub Actions workflow `products.yml` работает на существующем российском runner ежедневно в 06:15 UTC (09:15 МСК) и вручную. Общая с календарным workflow группа concurrency `history` предотвращает одновременную запись ветки `data`. Ветка уже должна существовать: её создаёт календарный workflow.

Сборщик публикует `products.json`, schemaVersion 1. В нём сохраняются исходные строки ТН ВЭД/ОКПД 2, разделы, примечания, исключения и бытовые примеры. Расшифровки добавляются как пояснения кодов, включая коды, упомянутые в исключениях. Это не отдельные положительные утверждения о маркировке товара.

`sourceHash` относится к содержимому страницы без пояснений; `revision` учитывает используемые пояснения, но не время проверки. `changedAt` меняется только при изменении содержания; `checkedAt` — после успешной проверки источника. При ошибке группы остаётся вся её предыдущая версия с прежней датой проверки. Другие группы могут обновиться. При первой загрузке публикуются успешно проверенные группы, а отсутствующие явно попадают в ошибки. Полностью пустой каталог не публикуется.

Возврат `0` означает успешную проверку всех групп, `2` — отказ хотя бы одной, `4` — общую ошибку чтения/записи. В Actions доступны строки `PRODUCTS_CHANGED`, `PRODUCTS_UNCHANGED`, `PRODUCTS_FAILED`, `UNKNOWN_CODES`. При частичном отказе сначала публикуются сохранённые и успешно проверенные группы, затем задание завершается ошибкой. Сводка и текстовые фрагменты отклонённых публичных разделов сохраняются в artifact `products-check` на 14 дней; они не коммитятся в `data`.

Справочник не меняет календарный манифест, историю и RSS. Приложение скачивает отдельный JSON с `raw.githubusercontent.com`, проверяет его, сохраняет атомарно в `products.json` каталога пользовательских данных и использует последнюю успешную либо встроенную версию. Ошибки этого канала не блокируют календарь. Настройка `Общие данные: история и товарные перечни` отключает обе загрузки, сохраняя уже имеющиеся данные.

## Проверка и обновление подписей

1. Откройте действующую [ТН ВЭД ЕАЭС на сайте ЕЭК](https://eec.eaeunion.org/comission/department/catr/ett/) и соответствующий PDF группы. Найдите точный код вместе со всеми промежуточными родительскими позициями, в том числе строками без собственного кода.
2. В `assets/products/names.json` добавьте или исправьте точный ключ кода: `name` — понятная краткая подпись, `sourceContext` — полная цепочка описаний от позиции к нужной подпозиции, `sourceUrl` — проверенный HTTPS-адрес ЕЭК. `searchTerms` содержит только проверенные обычные названия, не произвольные товары. Ведущие нули сохраняются.
3. Не выводите расшифровку по одному префиксу. «Прочие» имеет смысл только с родителями. Не назначайте код бытовому примеру из ЧЗ. Непроверенный код остаётся без пояснения и попадает в `UNKNOWN_CODES`.
4. Запустите автономные тесты и dry-run. Изменённые подписи попадут в ревизию группы при следующем сборе. Встроенную копию обновляйте из проверенного результата перед релизом.

Словарь содержит 176 проверенных точных позиций ЕЭК. Для большинства групп понятные названия берутся непосредственно из ЧЗ. У напитков, меховых изделий и спортивного питания часть перечней состоит только из кодов: заголовок ЧЗ сохраняется как название раздела, отдельно доступна расшифровка кода с полной иерархией ЕЭК. Исходные этапы и виды упаковки не выдаются за названия товаров.

Неподтверждённые коды перечисляются в `UNKNOWN_CODES` и остаются без выдуманной расшифровки; отсутствие словарной записи не мешает показать исходное наименование ЧЗ. Нестандартные пробелы в `2202 99110 0` допускают точное совпадение с `2202991100`; девятизначный `293629000` является опубликованной промежуточной позицией ЕЭК. Код `3405 40 00 0` из cosmetics сохранён дословно без исправления. Для `3504` источник ЕЭК содержит объединённую строку `3504 00`, поэтому автоматическая подстановка по префиксу не применяется.

## Когда ЧЗ меняет HTML

Скачайте публичную страницу, сравните товарный раздел с прежним. Исправляйте только разбор изменившейся разметки в `build/products.py`. Сборщик поддерживает таблицы и карточки, в том числе несколько этапов, объединённые ячейки, смену классификатора и дополнительные медицинские классификаторы. Проверяемая структура источников хранится в `assets/products/sources.json`; исчезновение ожидаемых таблиц, карточек или примечаний считается отказом. Законное удаление существенного условия тоже требует ручной сверки перед ослаблением проверки. Не принимайте HTML-оболочку HTTP 200 за пустой перечень.

Обновите соответствующий минимальный HTML в `tests/fixtures/products`, сохранив строки, условия и примеры без служебных форм или сессий. Один регрессионный тест должен воспроизводить реальное изменение. Сверьте итог с полной страницей, включая примечания вне таблиц, общие ограничения и дополнительные классификаторы. Названия и коды в этих HTML-фикстурах служат только автономным тестам; рабочий сборщик читает живые страницы.

```powershell
python build/test_products.py
python build/products.py check --data build/.work/products-check --dry-run
```

`--dry-run` ничего не записывает. Для сравнения с предыдущей версией заранее поместите её `products.json` в указанный каталог. Живая проверка 18.09.2026 выполнена от пользователя службы на российском runner: все три группы разобраны, `PRODUCTS_FAILED` пуст, единственный неизвестный код — указанный выше. Рабочие службы и опубликованные данные при этой проверке не менялись.

## Встроенный снимок и приёмка

`src/MarkingCalendar.App/Resources/bundled-products.json` обеспечивает первый запуск без сети. `build/update-bundled.ps1 -FromPublic` получает его отдельно от календарного манифеста; при отсутствии или повреждении файла сохраняет текущую встроенную версию. Проверка: `pwsh -NoProfile -File build/test-update-bundled.ps1`. C#-тест также читает настоящий встроенный ресурс и проверяет контракт.

Перед выпуском проверьте список прямо в карточке игрушек без URL события, кнопку страницы группы, меню справочника, группу без событий, поиск «шампунь», «зубные ёршики», код с пробелами и код из исключения `3307410000`. Условия должны быть видны, поиск и выбор группы сохраняться при обновлении модели, профиль — не меняться. Проверьте первый запуск без сети, ошибку загрузки после кеширования, светлую/тёмную тему и узкое окно.

Перечень игрушек дополнительно проверен живым запросом 18.09.2026 с рабочей машины. Названия показываются непосредственно в карточке события; коды остаются в раскрываемых подробностях.

## Оповещения о сбоях

При ошибке любой группы или публикации отдельное задание на GitHub runner отправляет сообщение в Telegram через существующие секреты `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`. Оно получает журнал из artifact сборщика; при отсутствии artifact отправляет сообщение об общем сбое задания. Это отделено от российского runner: при проверке 18.09.2026 доступ к Telegram API с него отсутствовал. Сообщение содержит названия сломавшихся групп, причины и ссылку на конкретный запуск Actions с полной диагностикой. Успешный запуск сообщений не отправляет. Если сбой сохраняется, следующий ежедневный запуск повторит уведомление; ошибки отправки также завершают шаг с ошибкой, а отсутствие секретов не считается успешной доставкой.

Обход последовательный, сетевой тайм-аут одной страницы — 30 секунд; лимит задания — 35 минут, чтобы даже массовый сетевой отказ оставил время на итоговую диагностику и уведомление. Оповещение действует после попадания workflow в основную ветку. Тесты сообщений не отправляют реальные Telegram-запросы.

## Проверка расширенного набора 18.09.2026

Живой обход всех 50 адресов получил 49 перечней; единственный отказ — HTTP404 chemistry. Финальный каталог содержит 349 товарных строк и 176 словарных расшифровок. Он проверен по контракту C#; структурные изменения парсера дополнительно проверены на сохранённых реальных HTML тех же источников.

Пройдены 12 тестов сборщика, 3 теста уведомлений, 97 UI-тестов, 110 тестов приложения и PowerShell-проверка обновления встроенного снимка. В браузере проверены новые группы, поиск «норки» по пояснению ЕЭК и расположение молочных товаров под событиями. Независимое ревью воспроизвело и затем подтвердило исправление потери названия, дополнительного медицинского классификатора и примечания об исключениях икры. Реальная доставка Telegram при проверке не вызывалась; наличие обоих секретов в GitHub подтверждено.
