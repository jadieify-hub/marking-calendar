# Все товарные группы и контроль сборщика

Запрос: охватить все группы календаря, автоматически сигнализировать о поломке любой группы.

1. Проверить фактические источники для всех записей карты групп. Сохранить точные адреса; разбирать опубликованные названия, коды и условия, не придумывать товары по названию группы.
2. Расширить существующий сборщик на найденные форматы. Убрать список четырёх пилотных групп. Ошибка одной страницы сохраняет её прежнюю версию и дату проверки, остальные обновляются. Отсутствие ожидаемой структуры — ошибка, а не пустой результат. При первом сборе публикуются успешно проверенные группы с явным сигналом о недоступных; полностью пустой каталог не публикуется. Это необходимо, поскольку legacy-страница chemistry уже возвращает 404 и не должна блокировать остальные 49 источников.
3. При ошибке проверки или публикации отправлять в уже настроенный Telegram название группы, причину и ссылку на журнал GitHub Actions. Неуспех доставки также виден в Actions. Успешные проверки молчат; повторный ежедневный отказ повторяет сигнал до исправления.
4. Обновить встроенный каталог и точные ссылки карты, сохранить согласованный интерфейс: события, ссылка на группу, затем товары.
5. Проверить реальные форматы автономными тестами, частичный отказ, уведомления без сетевой отправки; выполнить живую проверку, проверку контракта приложения и итоговое ревью. Обновить README и документацию сопровождения фактическими результатами.

Расширение выполняется в существующей ветке `codex/product-lists`. Публикация и выпуск в этот запрос не входят.

## Результат

Пункты 1–5 выполнены. 49 действующих перечней (349 строк) включены во встроенный каталог; недоступная chemistry остаётся в ежедневном обходе и ошибках. Уведомления подготовлены в workflow; активируются после публикации в основной ветке. Проверки: 12 parser + 3 alerts + 97 UI + 110 App, PowerShell, живая проверка источников и независимое ревью. Контракт C# не ослаблялся. Изменения подготовлены локально, выпуск не выполнялся.
