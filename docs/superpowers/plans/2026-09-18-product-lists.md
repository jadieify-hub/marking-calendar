# Понятные товарные перечни — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking. Этот документ разрешает подготовку и ревью плана; реализацию начинать только по отдельному запросу пользователя.

**Goal:** В календаре можно найти виды товаров по понятному названию или коду ТН ВЭД, прочитать исходные ограничения и открыть официальный источник, в том числе без событий группы и без интернета.

**Architecture:** Отдельный JSON-справочник в существующей ветке `data`, который получает публичные страницы ЧЗ на существующем российском runner. Проверенные короткие расшифровки хранятся в репозитории; приложение получает только подготовленный JSON, сохраняет его атомарно и показывает в отдельном диалоге. Календарные события, профиль пользователя и история дат остаются самостоятельными данными.

**Tech Stack:** Существующие .NET 8 / WPF / WebView2, TypeScript / Vite / Vitest; Python 3 stdlib (`HTMLParser`, `urllib`, `json`, `hashlib`, `unittest`) для трёх известных форматов страниц. Новые зависимости не нужны.

**Spec:** [Исследование от 18.09.2026](../../tnved-product-lists-research.md).

**Статус:** Реализовано 18.09.2026 в ветке `codex/product-lists`. Ревью данных, backend и итоговое ревью пройдены, замечания исправлены. Проверки: 286 .NET, 96 UI, 6 Python, PowerShell обновления ресурсов; живая проверка трёх страниц на российском runner. Релиз не публиковался.

## Global Constraints

- Первый выпуск охватывает товары для дома, косметику/бытовую химию и бакалею. Игрушки входят только в исправление внешней ссылки; полный импорт остальных групп — отдельное расширение.
- Названия описывают виды продукции, не отдельные бренды, артикулы или GTIN.
- Сохранять исходные формулировки, коды, этапы, примечания и исключения. Не выводить юридическую обязательность маркировки из одного названия или совпавшего кода.
- Не генерировать даты событий из товарных перечней. Не изменять выбранные пользователем группы, режим «Только мои», категории и историю календаря.
- Не применять ИИ при загрузке данных; не использовать внутренний `dev:codeSearch` единственным источником; не загружать полную номенклатуру ТН ВЭД в приложение.
- Использовать существующие GitHub `data`, российский runner, `AtomicFileWriter`, JSON-настройки, диалог и механизм открытия внешних ссылок.
- Расшифровки готовятся и сверяются один раз для кодов пилотных перечней; новые неподтверждённые подписи не придумывать автоматически.
- Реализация не включает публикацию релиза. Пользовательские заметки выпуска, README и снимки нового интерфейса подготовить вместе с реализацией; выпуск выполняется отдельно.

## Контракт данных и правила отображения

Один файл `products.json`, схема `1`. Без изменения существующего `manifest.json`: адрес фиксирован в новом клиенте рядом с адресом официальной общей истории. Старые версии приложения игнорируют новый файл. Схема `groups.json` остаётся `2`; необязательное `goodsUrl` обратно совместимо, поскольку текущий JSON-десериализатор игнорирует неизвестные поля.

Новые records в одном `src/MarkingCalendar.Core/Products/ProductCatalog.cs`:

```csharp
public sealed record ProductCodeMeaning(
    string Code, string Name, IReadOnlyList<string> SearchTerms,
    string SourceUrl, string SourceContext);
public sealed record ProductListRow(
    string Section, string SourceName, string TnvedText, string Okpd2Text,
    string Conditions, IReadOnlyList<ProductCodeMeaning> Meanings);
public sealed record ProductListGroup(
    string Id, string Name, string SourceUrl, string SourceHeading,
    string SourceHash, string Revision, DateTimeOffset ChangedAt,
    DateTimeOffset CheckedAt, string Conditions,
    IReadOnlyList<string> Examples, IReadOnlyList<ProductListRow> Rows);
public sealed record ProductCatalog(
    int SchemaVersion, string Revision, IReadOnlyList<ProductListGroup> Groups);
```

- `Id` — существующий project slug (`homeware`, `cosmetics`, `grocery`), связь с картой групп по нормализованному `Link`, а не русскому названию. Переименование названия не создаёт новую группу.
- `Section` хранит исходный заголовок этапа как текст. Дата из него не превращается в новое событие календаря.
- `TnvedText`, `Okpd2Text`, `Conditions` сохраняют ограничения вроде «кроме», «из», «в части»; строки кодов не превращаются в числа. Абзацы и списки сохраняются переносами строк.
- `Meanings` — словарные пояснения упомянутых кодов, а не вывод «все эти товары маркируются». Их заголовок в UI: «Что означают коды». Исходный перечень и исключения всегда доступны в той же карточке. Упоминание кода среди исключений не создаёт отдельную положительную товарную позицию.
- `SearchTerms` — проверенные синонимы/примеры под конкретным кодом. Например, для `3305` допустим поиск «шампунь» при сохранении названия родительской позиции «Средства для волос». Не раздавать всем кодам строки общее название этой строки.
- `SourceContext` сохраняет родительское описание ЕЭК: подпись «прочие» без контекста запрещена. Примечание о медицинском назначении не заменяется бытовым названием.
- `Examples` — примеры со страницы ЧЗ на уровне всей группы; они не получают выдуманного соответствия отдельному коду.
- `SourceHash` — SHA-256 нормализованного извлечённого содержимого раздела, включая условия и примеры. Меню, счётчики и рекламные блоки не входят.
- `Revision` группы учитывает исходное содержимое и применённые словарные подписи. Общая `Revision` учитывает группы в стабильном порядке. `CheckedAt` не входит в хеш: проверка без изменений не создаёт уведомление об изменении.
- `ChangedAt` меняется только при содержательном изменении; `CheckedAt` только при успешной проверке этой группы. Это время нашей проверки, не дата публикации нормативного документа.
- На первом запуске встроенный каталог; затем последняя валидная локальная версия. Отсутствующий новый файл в старом канале данных допустим.

## Критерии завершения

1. Все строки и условия трёх проверенных перечней доступны; исходные коды сохранены.
2. Понятные подписи проверены по источнику; неизвестный/неоднозначный код не получает выдуманной расшифровки.
3. Группа без событий находится через меню, без изменения календарных фильтров и профиля.
4. Справочник работает offline; ошибки не стирают последнюю успешную версию и не блокируют другой канал данных.
5. Изменение примечаний обнаруживается, а новая дата проверки без изменения содержимого не считается новыми товарами.
6. Старые установки работают с прежними схемами; новый клиент работает при отсутствии products.json.
7. Проверки проходят, README обновлён, известные замечания по этой задаче закрыты. Реализация на этом останавливается.
